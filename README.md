## 카페 유형·뷰 정리 (2026-11-14 기준)

### 작성 기준

- **유형(`type`)**: 사람들이 "OO카페"로 검색하는 분류. 붙여쓰기로 쓰고 항상 "카페"로 끝낸다. (예: `오션뷰카페`, `창고형카페`)
  - `cafe-basic.json`과 `cafe-details.json` 두 곳에 있으므로 **같이 고친다.** (화면은 `basic` 값을 사용)
  - 너무 넓은 표현은 쓰지 않는다. (`자연경관카페` ✗ → 뷰의 `자연경관뷰`로)
  - `베이커리카페`, `브런치카페`, `저수지뷰카페`는 유형에서 뺐다. (베이커리·브런치는 서비스, 저수지는 뷰에 있음)
- **뷰(`view`)**: 카페에서 보이는 풍경 종류. `cafe-details.json`에만 있다.
  - 지명은 빼고 풍경 종류만 쓴다. (`오남저수지뷰` → `저수지뷰`, `청풍호뷰` → `호수뷰`) 지명은 설명문에 쓴다.
  - 같은 뜻은 하나로 쓴다. (`바다뷰` → `오션뷰`)
  - 제주 `성산뷰`, `우도뷰`처럼 그 자체가 유명한 풍경은 지명을 써도 된다.
- **서비스(`services`)**: 카페에서 먹거나 이용할 수 있는 것. (`베이커리`, `브런치`, `포토존` 등) `cafe-details.json`에만 있다.
  - 모든 카페에 있는 `카페`는 취향 페이지(`/taste`) 필터에서 자동으로 빠진다.
- **추천 목적(`purpose`)**: 어떤 때 가면 좋은지. (`데이트`, `가족`, `드라이브` 등) `cafe-details.json`에만 있다.
- **공간 특징(`features`)**: 공간·건축의 특징. 카페마다 고유한 내용이 많아 취향 페이지(`/taste`) 필터에는 **2곳 이상에 있는 특징만** 나온다. 필터에 나오게 하려면 같은 표현으로 맞춘다. (`넓은 실내공간` → `대형 실내공간`처럼)
- **좌석(`seating`)**: 첫 번째는 좌석 수(`약 200석 정도`), 두 번째부터는 아래 좌석 종류 중에서만 고른다.
  - `실내 좌석`, `다양한 형태의 좌석`처럼 모든 카페에 해당하거나 정보가 없는 말은 쓰지 않는다.
  - 전망 좌석(`오션뷰 좌석`, `연못 전망 좌석`)은 `창가 좌석`으로 쓴다. 풍경은 뷰에 있다.
  - 좌석 간격·층고처럼 공간 이야기는 공간 특징에 쓴다.
- **반려동물(`pet`)**: 첫 번째는 동반 수준으로 `가능`(실내 포함) / `일부 구역 가능`(실내 펫존 등) / `야외만 가능` / `불가` 중 하나만 쓴다.
  - 두 번째부터는 조건(`케이지 필수`, `리드줄 필수`, `기저귀 필수`, `소형견만`)이나 장소(`펫존 있음`, `야외 정원`, `야외 테라스`)를 쓴다.
  - 목록·취향 페이지는 첫 번째 값으로 판단하므로, 야외 동반이 되면 첫 칸을 `불가`로 쓰지 않는다.
- **설명**: `cafe-basic.json`에 두 가지를 쓴다.
  - `summary`: 60~80자 한 문장. 검색 결과·공유 미리보기(meta, og) 설명으로 쓴다. 지역 + 이름 + 유형 + 대표 특징을 넣는다.
  - `description`: 300~600자. 상세 페이지 본문과 카드 소개 글로 쓴다.
